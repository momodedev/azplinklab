GitHub Copilot: **What the Script Does**
`setupsimlab.ps1` builds Azure networking and an optional Windows VM as a foundation for an Azure Migrate private-endpoint lab. It does **not** create the Azure Migrate project or configure its service-managed private endpoints.

1. **Reads deployment options.** Parameters let you choose a subscription, existing resource group, region, resource-name prefix, address ranges, VM settings, and whether to deploy the VM. By default, the target group is `rg-infra-winmig-apac-v-chengzhiz-poc`, VM deployment is enabled, and the VM size is `Standard_D8s_v5`.

2. **Checks whether to proceed.** The script supports `-WhatIf` and `-Confirm` through `ShouldProcess`. In this script, `-WhatIf` exits immediately at the start; it does not produce a preview of each Azure resource operation.

3. **Loads Azure PowerShell modules and selects a subscription.** It imports `Az.Accounts`, `Az.Resources`, `Az.Network`, and `Az.Compute`. If modules are missing, it can install them when run with `-InstallAzModules`. It uses the current Azure login unless a subscription ID is supplied, then selects that subscription.

4. **Checks the existing resource group and chooses a region.** It looks up the named resource group and stops if it cannot find it. If `-Location` is omitted, it uses the resource group’s region. In the Cloud Shell run you shared, that region was `westus2`. The script does not create the resource group.

5. **Validates network address ranges.** It parses the IPv4 CIDRs, checks that the two VNet address spaces do not overlap, verifies each subnet is fully contained in its VNet, and checks that the two Azure Migrate subnets do not overlap. These checks run before provider registration and resource creation.

6. **Registers Azure resource providers.** It checks and, if needed, registers providers for networking, compute, storage, Key Vault, Migrate, and Recovery Services. When registration is needed, it polls until registration completes or times out. Provider registration changes subscription state.

7. **Creates or updates the appliance network security group.** The NSG allows TCP 44368 and 3389 from the simulated on-premises VNet’s address range, then explicitly denies those ports from other sources. If the NSG already exists, the script reconciles its named rules and stops if an unrelated rule occupies one of its chosen priorities.

8. **Creates outbound NAT resources.** It creates a Standard public IP and NAT Gateway if they do not already exist. The gateway provides outbound connectivity for the appliance subnet; the VM itself is not assigned a public IP.

9. **Creates the simulated on-premises VNet.** It creates or updates the VNet using `10.20.0.0/16` by default. Its `snet-appliance` subnet uses `10.20.1.0/24` and is associated with the NSG and NAT Gateway.

10. **Creates the Azure Migrate VNet and subnets.** It creates or updates a VNet using `10.30.0.0/16` by default. It adds:
   - `snet-private-endpoint` (`10.30.1.0/24`), with private endpoint network policies disabled.
   - `snet-dns-inbound` (`10.30.2.0/28`), delegated to `Microsoft.Network/dnsResolvers`.

11. **Creates two VNet peerings.** Each VNet gets a peering to the other, with forwarded traffic allowed. With the installed Az.Network cmdlet, VNet access is enabled by default; the script does not use the unsupported `-AllowVirtualNetworkAccess` parameter. It later checks that both peerings reach `Connected`.

12. **Creates an Azure DNS Private Resolver and inbound endpoint.** It uses Azure Resource Manager REST API version `2022-07-01` to create or update the resolver in the Azure Migrate VNet, then creates an inbound endpoint in the delegated DNS subnet. It polls each resource until its provisioning state is `Succeeded` and reports the inbound IP.

13. **Optionally creates the appliance VM.** Because `DeployApplianceVM` defaults to `$true`, the script prompts for a local administrator credential and creates a Windows Server 2022 VM by default. It creates a NIC on the appliance subnet, uses a 128-GB Premium SSD OS disk, and does not attach a public IP. If the VM already exists, it leaves it unchanged.

14. **Performs a limited post-deployment check and prints next steps.** It verifies peering state and prints a resource summary. It also tells you to create the Azure Migrate project, select private endpoint connectivity, generate the key, and install the appliance. It recommends linking Azure Migrate’s private DNS zones to both VNets; the script itself does not create those zones or links.

**Cost and Validation Notes**
The script creates billable resources, notably a NAT Gateway and public IP, and by default a VM and managed disk. Check the target subscription, permissions, available VM capacity, and expected costs before running it. Its final automated validation confirms peering state, but does not verify VM health, DNS resolution, outbound connectivity, or Azure Migrate endpoint reachability.

    $addresses = @()
    $dnsError = $null

    try {
        $answers = Resolve-DnsName -Name $item.Fqdn -Type A -DnsOnly -ErrorAction Stop
        $addresses = @(
            $answers |
                Where-Object Type -eq 'A' |
                Select-Object -ExpandProperty IPAddress -Unique
        )
    } catch {
        $dnsError = $_.Exception.Message
    }

    $tcpSucceeded = $false
    $remoteAddress = ''
    try {
        $tcp = Test-NetConnection -ComputerName $item.Fqdn -Port 443 -InformationLevel Detailed -WarningAction SilentlyContinue
        $tcpSucceeded = $tcp.TcpTestSucceeded
        $remoteAddress = [string]$tcp.RemoteAddress
    } catch {
        $tcpSucceeded = $false
    }

    [pscustomobject]@{
        Fqdn         = $item.Fqdn
        ExpectedIP   = $item.ExpectedIp
        ResolvedIPs  = $addresses -join ', '
        DNSMatches   = ($addresses -contains $item.ExpectedIp)

**2. Confirm HTTPS/TLS connectivity**

A successful TCP check proves a connection to port 443, but does not by itself confirm TLS. The VM should have `curl.exe` available. Run:

```powershell
foreach ($item in $checks) {
    Write-Host "`nTesting HTTPS: $($item.Fqdn)"
    & curl.exe --silent --show-error --output NUL --write-out "HTTP %{http_code}`n" --connect-timeout 10 --max-time 20 "https://$($item.Fqdn)/"
    Write-Host "curl exit code: $LASTEXITCODE"
}
```

An HTTP status such as `200`, `403`, or `404` still indicates that the server was reached and returned an HTTPS response; the service may not support a request to `/`. A `curl` exit code of `0` is the expected transport/TLS result. An exit code other than `0`, especially with certificate, name-resolution, or timeout errors, needs investigation.
